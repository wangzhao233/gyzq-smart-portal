# 审批流 03：审批操作

## 你在哪里

已在 `02-todo-detail.md` 中打开了审批详情弹窗。你可以执行审批操作：办理、驳回、加签、终止、抄送、委托、暂存、标记。

## 操作方式总览

所有按钮通过 `bsk snapshot` 快照定位 @eN ref 后操作。

### 主操作按钮栏

`bsk snapshot` 查找对话框中以下文字对应的按钮：

| 操作 | 按钮文字 | 说明 |
|------|---------|------|
| 办理 | `"办理"` | 弹出意见/选人弹窗 |
| 驳回 | `"驳回"` | 弹出节点选择 + 重提交方式 + 意见弹窗 |
| 加签 | `"加签"` | 弹出加签方式(radio) + 选人弹窗 |
| 暂存 | `"暂存"` | 无弹窗，直接保存 |
| 更多 | `""` 图标按钮 | 展开下拉菜单(终止/抄送/委托/标记) |

### 更多下拉菜单

点击「更多」按钮后，`bsk snapshot` 查看新出现的 listitem，查找：

| 操作 | 按钮文字 | 说明 |
|------|---------|------|
| 标记 | `"标记"` | 无弹窗，直接切换 |
| 终止 | `"终止"` | 弹出警告 + 意见弹窗（高危⚠️，需用户确认） |
| 抄送 | `"抄送"` | 弹出选人 + 意见弹窗 |
| 委托 | `"委托"` | 弹出选人 + 意见弹窗 |

> 每次点完按钮或关闭弹窗后，下拉菜单会收起。再点「更多」重新展开。

## 各按钮操作详情

### 办理

`bsk click @eN "办理"` → 弹出「办理」dialog

- **下一节点为"人工任务"**：dialog 含处理人「选择人员」+ 意见输入
  - 操作：搜索选人 → 选人弹窗「确定」→ 办理弹窗「确定」
  - 具体流程见 `06-post-action.md`
- **下一节点为"结束事件"**：dialog 仅含意见输入 + 取 消/确 定
  - 操作：填写意见(可选) → `bsk click @eN "确 定"`

### 驳回

`bsk click @eN "驳回"` → 弹出「驳回」dialog

弹窗包含：
- `textbox "请选择节点"` → 驳回节点选择
- `radio "重新流转"` / `radio "直接回到当前节点"` → 驳回后重新提交方式
- `Iframe` 编辑区 → 填写理由

操作：选择驳回节点 + 选择重提交方式 + 填写意见 → `bsk click @eN "确 定"`

### 加签

`bsk click @eN "加签"` → 弹出「加签」dialog

弹窗包含（加签方式 radio）：
- `radio "加会签"` — 在当前节点中添加处理人
- `radio "加前签"` — 在当前节点之前添加处理人
- `radio "加后签"` — 审批通过，并在当前节点之后添加处理人
- `StaticText "选择人员"` → 选人弹窗

操作：选择加签方式 → 选择人员 → `bsk click @eN "确 定"`

### 终止

⚠️ **高危操作，会直接结束整个流程，执行前必须让用户明确确认。**

`bsk click @eN "终止"`（从更多下拉）→ 弹出「终止」dialog

弹窗包含：警告文本 + 意见输入(`Iframe`) + 取 消/确 定

### 抄送

`bsk click @eN "抄送"`（从更多下拉）→ 弹出「抄送」dialog

弹窗包含：选择人员 + 意见输入 + 取 消/确 定

### 委托

`bsk click @eN "委托"`（从更多下拉）→ 弹出「委托」dialog

弹窗包含：选择人员 + 意见输入 + 取 消/确 定

### 暂存

`bsk click @eN "暂存"` → 无弹窗，直接保存，页面状态不变。

### 标记

`bsk click @eN "标记"`（从更多下拉）→ 无弹窗，直接切换标记状态。

## 操作结果检测（所有审批按钮共用）

点击任意审批按钮（办理/驳回/终止等）并确认弹窗后：

1. **点击** → `bsk click @eN "确 定"`
2. **2秒后** → `bsk snapshot` — 捕捉短提示消息（约 3 秒消失）
3. **5秒后** → `bsk snapshot` — 检查页面状态变化
4. 页面无变化 → `bsk evaluate` 查看接口返回值
   ```
   bsk evaluate →
     const e = performance.getEntriesByType('resource')
       .filter(x => x.initiatorType === 'fetch' || x.initiatorType === 'xmlhttprequest');
     e[e.length - 1]?.name + ' status:' + e[e.length - 1]?.responseStatus
   ```
5. 接口报错 → 提取错误告知用户；正常 → 询问用户手动确认

（详见 `core/01-global-rules.md` GR-08）

## 审批操作安全规则

| 操作 | 风险等级 | 确认要求 |
|------|---------|---------|
| 办理 | 中 | 建议确认，用户明确说"通过"时可直接执行 |
| 驳回 | **高** | **必须确认** — 驳回不可逆 |
| 终止 | **高** | **必须确认** — 终止会结束整个流程 |
| 加签 | 低 | 可直接执行 |
| 暂存 | 无 | 直接执行 |
| 抄送 | 低 | 可直接执行 |
| 委托 | 中 | 建议确认 |

## 操作失败处理

| 失败场景 | 处理方式 | 回退 |
|----------|---------|------|
| 审批按钮找不到 | `bsk snapshot` 检查；可能无此操作权限 | 留本节点 |
| `getFormFields` 返回 null | 降级 `bsk snapshot` | 留本节点 |
| 办理/驳回后弹窗确认失败 | 按 `05-popup-handle.md` 弹窗处理规则重试 | → `05-popup-handle.md` |

## 审批完成后的流程

审批操作经弹窗确认后：
- 办理/驳回/加签/抄送/委托 → **`05-popup-handle.md`（弹窗确认）→ `06-post-action.md`（选人/意见）→ 完成**
- 终止 → **`05-popup-handle.md`（弹窗确认）→ 完成**
- 暂存/标记 → 留本节点

> **审批流程不走站点记忆。**
