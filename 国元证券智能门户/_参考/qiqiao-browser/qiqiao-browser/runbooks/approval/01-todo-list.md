# 审批流 01：待办列表页

> ⚠️ 开始前先读取 `core/06-discipline-check.md`。

## 你在哪里

已从首页点击"待办列表"进入，看到所有待审批的流程列表。页面上方有搜索框和筛选条件，列表中每条待办可以点击打开详情。

## 本节点分叉

本节点是审批流的入口，有 **4 个分叉**：

| 分叉 | 场景 | 去向 |
|------|------|------|
| **A — 查看列表数据** | 用户想看当前有哪些待办 | 搜索/筛选/浏览 → 展示结果，留本节点 |
| **B — 详情编辑 → 填单** | 点击待办打开详情，修改表单字段 | → `02-todo-detail.md`（编辑模式） |
| **C — 审批按钮操作** | 点击待办打开详情，执行审批 | → `02-todo-detail.md` → `03-approval-action.md` |
| **D — 评论操作** | 点击待办打开详情，发送评论 | → `02-todo-detail.md` → `04-comment.md` |

---

## 分叉 A：查看当前待办列表数据

> ⚠️ 数据查询规则（GR-01-9）：用户要求查看待办列表数据时，**必须用 `bsk snapshot` 获取最新快照**，禁止使用缓存上下文。每次查询都重新 snapshot。

### 搜索待办

```
bsk snapshot → 找搜索框 @eN
bsk fill @eN --value "关键词"
bsk press Enter --ref @eN
```

### 筛选

| 操作 | 方式 |
|------|------|
| 按流程名称筛选 | 点击筛选下拉框选择 |
| 按应用名称筛选 | 点击筛选下拉框选择 |
| 按流程状态筛选 | 点击筛选下拉框选择 |

筛选控件为下拉选择类，`bsk click @eN` 点击后选择对应选项，列表自动刷新。

---

## 分叉 B / C / D：点击待办打开详情

分支 B/C/D 的第一步都是点击待办列表中的条目，打开详情弹窗。

### 按关键词匹配

```
bsk evaluate → window.$ai.findDom('关键词')
```

| 结果 | 处理 |
|------|------|
| 无结果 | 提示用户，换个关键词 |
| 唯一结果 | `[0].click()` → 进入 `02-todo-detail.md` |
| 多个结果 | 展示 `getMetadata()` 让用户确认 |

### 直接点击

如果用户说"第 X 条"或"某某的那个"，用 `bsk snapshot` 获取列表数据，匹配后 `bsk click @eN`。

---

## 批量操作（特殊场景）

| 操作 | 流程 | 去向 |
|------|------|------|
| 批量提交 | 批量模式 → 勾选 → 提交 | → `05-popup-handle.md` |
| 批量转交 | 批量模式 → 勾选 → 转交 | → `05-popup-handle.md` |
| 标记流程 | `window.$ai.findDom('标记流程')` | 留本节点 |

### 批量提交流程

```
1. bsk evaluate → window.$ai.findDom('批量处理')[0].click()
2. bsk evaluate → window.$ai.findDom('全选本页')[0].click()  // 或逐个勾选
3. bsk evaluate → window.$ai.findDom('批量提交')[0].click()
4. → 05-popup-handle.md（弹窗确认）
```

### 批量转交

前两步同批量提交，第 3 步改为 `window.$ai.findDom('批量转交')[0].click()`。

### 返回首页

```
bsk navigate "{PLATFORM_DOMAIN}/qiqiao2/runtime/"
```

## 操作失败处理

| 失败场景 | 处理方式 | 回退 |
|----------|---------|------|
| 搜索无结果 | 提示用户，换个关键词或清空筛选 | 留本节点 |
| 多条同名待办无法区分 | 展示发起人、时间等辅助判断 | 留本节点 |
| 批量操作按钮找不到 | `bsk snapshot` 检查页面状态 | 留本节点 |
