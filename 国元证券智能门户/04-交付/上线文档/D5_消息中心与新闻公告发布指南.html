D5 消息中心与新闻公告发布指南

1. 文档说明

1.1 适用范围

本指南适用于国元证券智能门户系统中的消息中心和新闻公告模块，面向内容管理员和信息发布人员，指导其完成消息发布、新闻公告管理、可见范围配置等日常操作。

1.2 读者对象

  • 内容管理员：负责新闻公告的编辑、审核与发布
  • 部门信息员：负责本部门消息的发布与管理
  • 系统管理员：负责第三方应用接入配置与权限管理
  • 普通用户：查看消息与新闻公告

1.3 术语说明

术语说明
消息中心智能门户统一消息汇聚、分发与推送模块，支持多通道消息投递
新闻公告面向组织的正式信息发布功能，支持富文本编辑、审核流程和可见范围控制
PORTAL通道消息通过智能门户Web端展示
QW通道消息通过企业微信工作台推送
可见范围消息/公告的受众范围，可按用户、部门、用户组三级配置
AppKey/Secret第三方系统接入消息中心的身份标识与密钥

2. 消息中心概述

2.1 功能定位

消息中心是智能门户的核心基础设施模块，为国元证券全组织（387个组织节点）提供统一的消息汇聚、分发与推送能力。消息中心支持以下核心能力：

  1. 统一消息入口：为内部第三方业务系统提供标准API，实现消息的统一接入
  2. 多终端覆盖：支持门户端（PORTAL）与企业微信端（QW）双通道推送
  3. 精细权限管控：基于企微通讯录体系，支持按用户、部门、用户组三级配置消息可见范围
  4. 全链路可追溯：记录消息的发布、送达、撤回等全生命周期日志

2.2 消息类型

消息中心支持三种消息类型，适用于不同业务场景：

消息类型说明适用场景展示样式
文本消息（text）纯文本内容的消息系统通知、提醒类消息简洁文本卡片
卡片消息（textcard）带标题、摘要和跳转链接的卡片待办提醒、审批通知、业务链接图文卡片，可点击跳转
图文消息（news）支持多图文组合的富文本消息新闻资讯、活动宣传图文并茂的展示卡片

2.3 推送通道

消息支持以下推送通道，可单独或组合使用：

通道标识说明
门户通道PORTAL消息在智能门户Web端的消息中心展示，用户登录后可见
企微通道QW消息推送至企业微信工作台，支持移动端实时接收
双通道PORTAL,QW同时推送至门户和企微，确保用户多端收到

3. 消息发布流程

3.1 通过管理后台发布消息

操作步骤

  1. 登录管理后台
    - 访问智能门户管理后台地址
    - 使用管理员账号登录
  1. 进入消息管理
    - 在左侧导航栏选择「消息中心」→「消息管理」
    - 点击「发布消息」按钮
  1. 编辑消息内容
    - 消息类型：选择 text / textcard / news
    - 消息标题：输入消息标题（必填，最大256字符）
    - 消息正文：输入消息内容（text/news类型必填）
    - 跳转链接：输入跳转URL（textcard类型选填）
    - 推送通道：选择 PORTAL / QW / 双通道
  1. 配置可见范围
    - 按用户：选择指定接收人
    - 按部门：选择接收部门
    - 按用户组：选择接收用户组
    - 详见第5节「可见范围配置」
  1. 发布消息
    - 确认内容无误后，点击「发布」
    - 系统将立即推送消息至指定通道和受众

3.2 通过API接口发布消息

第三方系统可通过API接口向消息中心提交消息，实现系统消息的统一推送。

接口信息

项目说明
接口地址POST /do1cloud-message-api/openapi/message/save
认证方式HMAC-SHA256签名认证
请求格式JSON
限流策略100次/秒/AppKey

请求参数

字段类型必填说明
msgTypeString是消息类型：text / textcard / news
titleString是消息标题
contentString是消息正文
terminalString是推送终端：PORTAL / QW（可逗号分隔多个）
usersString否可见用户企微ID列表（逗号分隔）
departmentsString否可见部门ID列表（逗号分隔）
userGroupsString否可见用户组ID列表（逗号分隔）
urlString否跳转链接（textcard类型使用）
sendWorkBenchBoolean否是否推送工作台，默认false

请求头

Header说明
X-AppKey应用标识（由管理员分配）
X-Timestamp请求时间戳（毫秒）
X-Nonce随机字符串（32位，防重放）
X-Sign签名 = HMAC-SHA256(AppSecret, body)，结果取十六进制小写

响应示例


{
    "code": 0,
    "msg": "success",
    "data": {
        "jobId": "MSG_20260614_001",
        "status": "QUEUED"
    }
}

错误码说明

错误码说明
0成功
401认证失败（AppKey无效 / 签名不匹配 / 时间戳过期）
403无权限（AppKey已禁用）
400参数校验失败
429请求频率超限
500服务内部错误

4. 消息类型说明

4.1 文本消息（text）

适用场景：系统通知、操作提醒、简单信息传达

内容要求：

  • 标题：必填，简洁明了，不超过256字符
  • 正文：必填，纯文本内容

示例：


标题：系统维护通知
内容：尊敬的用户，系统将于今晚22:00-23:00进行维护升级，届时服务将暂停。

4.2 卡片消息（textcard）

适用场景：待办提醒、审批通知、业务链接跳转

内容要求：

  • 标题：必填，突出重点，不超过256字符
  • 正文：必填，简要描述，引导用户点击
  • 跳转链接：选填，点击卡片后跳转的目标页面

示例：


标题：您有一条新的审批待办
内容：张三提交的差旅报销申请（¥3,500）等待您审批
链接：https://portal.oa.gyzq.com/approval/detail/12345

4.3 图文消息（news）

适用场景：新闻资讯、活动宣传、政策通知

内容要求：

  • 标题：必填，吸引注意力，不超过256字符
  • 正文：必填，支持富文本格式
  • 跳转链接：选填，查看详细内容的链接

5. 可见范围配置

5.1 配置方式

消息的可见范围支持三种维度的配置，可单独或组合使用：

维度说明适用场景
按用户指定具体的接收人个人通知、定向消息
按部门指定接收部门，部门内所有成员可见部门通知、组织公告
按用户组指定接收用户组，组内所有成员可见项目组通知、专项通知

5.2 配置规则

  1. 组合配置：三种维度可同时配置，取并集（即满足任一条件的用户都可见）
  2. 空配置处理：如果三种维度均未配置，消息将推送给全部用户（全组织可见）
  3. 部门层级：选择父部门时，其下属所有子部门的成员均可见
  4. 用户组管理：用户组由系统管理员在后台维护，内容管理员可直接引用

5.3 配置示例

示例1：全员通知

  • 可见范围：不配置（留空）
  • 效果：全组织387个节点的所有用户可见

示例2：部门通知

  • 可见范围：departments = "信息技术部"
  • 效果：信息技术部及其下属子部门的所有成员可见

示例3：定向通知

  • 可见范围：users = "张三,李四,王五"
  • 效果：仅张三、李四、王五三人可见

示例4：组合通知

  • 可见范围：departments = "总裁办" + userGroups = "高管群"
  • 效果：总裁办全体成员 + 高管群组成员均可见

6. 新闻公告发布流程

6.1 新闻公告功能概述

新闻公告是面向组织的正式信息发布功能，与普通消息的主要区别：

  • 支持富文本编辑（图文混排、表格、附件）
  • 支持审核流程（草稿→待审核→已发布）
  • 支持定时发布和撤回
  • 在门户首页以醒目位置展示

6.2 发布流程

第一步：创建草稿

  1. 登录管理后台
  2. 进入「新闻公告」→「公告管理」
  3. 点击「新建公告」
  4. 填写公告信息：
    - 公告标题：必填，突出主题
    - 公告分类：选择分类（当前共11个一级分类：部门简报、党建群团、风控合规、公司动态、公司文件、规划发展、交流论坛、全面从严治党、数字化转型、文化建设、子公司及分支机构。详见《新闻公告分类栏目ID对照表》）
    - 公告正文：支持富文本编辑，可插入图片、表格、附件
    - 封面图片：选填，用于门户首页展示
    - 可见范围：配置受众范围（参见第5节）
    - 发布时间：选择「立即发布」或「定时发布」
  1. 点击「保存草稿」

第二步：提交审核

  1. 确认公告内容无误
  2. 点击「提交审核」
  3. 系统自动通知审核人

第三步：审核通过

  1. 审核人登录后台，查看待审核公告
  2. 审核内容合规性、准确性
  3. 审核通过后，公告状态变更为「已发布」
  4. 系统自动推送消息至指定受众

6.3 公告审核规则

审核要点说明
内容合规是否符合公司信息发布规范，不包含敏感信息
准确性信息是否准确无误，数据是否有据可查
格式规范是否符合公文格式要求，排版是否清晰
可见范围受众范围是否合理，是否涉及跨部门发布

7. 公告审核流程

7.1 审核角色

角色权限说明
内容管理员创建、编辑、提交审核负责公告内容的编写
审核人审核通过、审核驳回负责公告内容的审核把关
系统管理员全部权限负责系统配置和权限管理

7.2 审核流程


草稿 → 提交审核 → 待审核 → 审核通过 → 已发布
                   ↓
               审核驳回 → 退回修改 → 重新提交

7.3 审核操作

  1. 查看待审核公告
    - 登录管理后台
    - 进入「新闻公告」→「审核管理」
    - 查看待审核列表
  1. 审核公告
    - 点击公告标题查看详情
    - 检查内容、格式、可见范围
    - 选择「通过」或「驳回」
    - 如驳回，需填写驳回原因
  1. 审核结果通知
    - 审核通过：系统自动发布并通知创建人
    - 审核驳回：系统通知创建人并附驳回原因

8. 公告撤回操作

8.1 撤回条件

  • 仅已发布的公告可撤回
  • 撤回后公告状态变更为「已撤回」
  • 已撤回的公告不可恢复，需重新创建

8.2 撤回步骤

  1. 登录管理后台
  2. 进入「新闻公告」→「公告管理」
  3. 找到需要撤回的公告
  4. 点击「撤回」按钮
  5. 确认撤回操作
  6. 系统将标记公告为「已撤回」，并通知已查看的用户

8.3 API撤回消息

第三方系统可通过API撤回已发送的消息：

接口地址：POST /do1cloud-message-api/openapi/message/revoke

请求参数：


{
    "jobId": "MSG_20260614_001"
}

说明：

  • jobId为消息发布时返回的消息标识
  • 撤回操作为写操作，使用POST方法
  • 撤回后，PORTAL通道标记消息为已撤回，QW通道推送撤回通知

9. 常见发布问题

9.1 消息发送失败

问题：消息发布后，用户未收到消息

排查步骤：

  1. 检查消息状态是否为「已发送」
  2. 检查可见范围配置是否正确
  3. 检查推送通道是否正常（PORTAL/QW）
  4. 查看操作日志是否有错误信息

解决方案：

  • 如可见范围配置错误，修改后重新发布
  • 如推送通道异常，联系技术支持排查
  • 如API调用失败，检查签名和参数是否正确

9.2 公告审核超时

问题：公告提交审核后长时间未审核

排查步骤：

  1. 确认审核人是否收到审核通知
  2. 检查审核人是否有权限审核
  3. 联系审核人确认是否收到待办提醒

解决方案：

  • 联系审核人尽快处理
  • 如审核人不可用，联系系统管理员调整审核流程

9.3 消息推送延迟

问题：消息发布后，用户收到消息有延迟

原因分析：

  • 企微通道推送延迟（网络或API响应慢）
  • 消息队列积压（高并发场景）
  • 用户未登录门户（PORTAL通道）

解决方案：

  • 企微通道延迟：检查企微API连接状态
  • 消息队列积压：联系运维检查队列状态
  • 用户未登录：建议用户使用企微通道接收消息

9.4 可见范围不生效

问题：配置了可见范围，但非目标用户也能看到消息

排查步骤：

  1. 检查可见范围配置是否保存成功
  2. 检查部门层级关系是否正确
  3. 检查用户组成员是否包含目标用户

解决方案：

  • 重新配置可见范围并保存
  • 联系系统管理员确认部门和用户组数据

9.5 API调用认证失败

问题：第三方系统调用API返回401错误

排查步骤：

  1. 检查AppKey是否有效
  2. 检查AppSecret是否正确
  3. 检查签名计算是否正确
  4. 检查时间戳是否在5分钟窗口内

解决方案：

  • 联系系统管理员确认AppKey/Secret
  • 检查签名计算逻辑（HMAC-SHA256）
  • 确保服务器时间同步

10. 第三方应用接入配置

10.1 申请接入

  1. 联系系统管理员，提交接入申请
  2. 提供以下信息：
    - 应用名称
    - 应用负责人
    - 应用用途说明
  3. 系统管理员分配AppKey和AppSecret

10.2 接入配置

配置项说明
AppKey应用唯一标识，用于API调用认证
AppSecret应用密钥，用于签名计算，请妥善保管
回调地址选填，用于接收消息状态回调
权限配置配置可发送的消息类型和推送通道

10.3 密钥管理

  • 密钥轮换：系统支持密钥轮换，轮换期间新旧密钥并行24小时
  • 安全存储：AppSecret需在服务端安全存储，禁止前端暴露
  • 泄露处理：如密钥泄露，立即联系管理员轮换密钥
