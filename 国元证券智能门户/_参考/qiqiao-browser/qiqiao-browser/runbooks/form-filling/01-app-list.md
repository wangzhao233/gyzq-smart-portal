# 填单流 01：应用列表页

> ⚠️ 开始前先读取 `core/06-discipline-check.md`。

## 你在哪里

已从首页进入应用列表，当前看到应用列表页面，页面上方有搜索框。本节点负责搜索和选择应用，进入应用详情页。

## 本节点产出

- 找到并点击了目标应用，进入了应用详情页

## 可执行操作

| # | 操作名 | 前置条件 | 执行方式 | 下一节点 |
|---|--------|---------|---------|---------|
| 1 | 搜索应用 | 用户指定了应用名 | 搜索框输入关键词 + 回车 | 留本节点 |
| 2 | 选择应用 | 搜索到唯一结果 | `window.$ai.findDom` 或 `bsk click @eN` 点击 | → `02-app-detail.md` |
| 3 | 确认后选择应用 | 搜索到多个结果 | 展示元数据让用户确认 | → `02-app-detail.md` |
| 4 | 返回首页 | 用户想换方向 | `bsk navigate` 回首页 | → `../common/30-home.md`（节点 30） |

### 操作 1：搜索应用

**搜索关键词预处理** — 用户说的名称常带后缀（如"请假应用"），去掉后缀再搜索。常见需去除的后缀：`应用`、`系统`、`平台`、`模块`、`管理`。

```
bsk snapshot → 找到搜索框的 @eN ref
bsk fill @eN --value "关键词"
bsk press Enter --ref @eN
```

> 也可以用 `window.$ai.findDom('搜索框')` 定位搜索框，如果更稳定的话优先用它。

### 操作 2：唯一结果 — 直接选择

```
bsk evaluate → window.$ai.findDom('应用名称关键词')[0].click()
```

### 操作 3：多个结果 — 用户确认

> ⚠️ **数据安全：** 匹配到多条数据时，必须让用户确认，**禁止**自行猜测。

```
bsk evaluate →
  const refs = window.$ai.findDom('应用名称关键词');
  refs.map(ref => window.$ai.getMetadata(ref));  // 获取元数据展示给用户
```

将 `name`、`desc`、`id` 展示给用户，让用户选择。

### 操作 4：返回首页

```
bsk navigate "{PLATFORM_DOMAIN}/qiqiao2/runtime/"
```

## 操作失败处理

| 失败场景 | 处理方式 | 回退 |
|----------|---------|------|
| 搜索框找不到 | 尝试同义词；询问用户 | 留本节点 |
| 搜索无结果 | 提示用户未找到，问是否换关键词 | 留本节点 |
| 搜索多个结果用户无法区分 | 展示更多元数据辅助判断 | 留本节点 |
| 点击应用后无响应 | `bsk snapshot` 检查页面，确认是否已跳转 | 留本节点 |

## 下一节点

操作 2/3 成功 → **`02-app-detail.md`（应用详情页）**
操作 4 → **`../common/30-home.md`（节点 30：首页）**
