# qiqiao-browser

七巧Plus 平台浏览器自动化技能。采用**主会话单线程节点流**架构：

- **所有节点都在主会话中执行**：环境检测 → 登录 → 意图识别与导航 → 流程节点 → 结果展示
- **不派发子代理 / 子任务**：每个流程节点由主会话按顺序读取对应 runbook 文件并逐项执行
- **关键原则**：任何时候主会话都清楚自己处于哪个节点；节点之间按"下一节点"声明顺序流转，不跳节点、不并行

---

## 架构全景

```
[10-环境检测] → [20-登录] → [30-首页/意图识别]
                                  │
              ┌───────────────────┼───────────────────┐
              ▼                   ▼                   ▼
        ┌───────────┐       ┌───────────┐       ┌───────────┐
        │  填单流    │       │  审批流    │       │ 发起流程   │
        │ 01→02→03  │       │ 01→02→03  │       │ 01→02→03  │
        │ →04→05→06 │       │ →04/05→06 │       │ →04→05    │
        └─────┬─────┘       └─────┬─────┘       └─────┬─────┘
              │                   │                   │
              └───────────────────┼───────────────────┘
                                  ▼
                       [任务完成 → 展示结果给用户]
```

- **主会话** 依次执行全部节点：`common/` 三个公共节点 + 对应流程文件夹下的节点序列
- **节点流转** 由每个 runbook 文件末尾的"下一节点"声明驱动，主会话读取目标文件后继续执行
- **需要用户输入时** 主会话直接在会话中询问，等待用户回复后从中断点继续，无需状态标记

## 文档读取阶段

**本技能按阶段加载文档，不在启动时一次读完所有文件：**

### 阶段一：技能加载时（立即读取）

1. 本文（你正在读）
2. `core/00-overview-and-flow.md` — 架构总览、流程路径
3. `recovery/00-resume-protocol.md` — 中断恢复协议

### 阶段二：登录成功、进入首页后（节点 30 执行前读取）

4. `core/01-global-rules.md` — 全局规则（GR-01 至 GR-09）
5. `core/02-state-model.md` — 状态变量字典
6. `core/05-commands-reference.md` — 指令参考手册（bsk CLI + window.$ai API）
7. `core/06-discipline-check.md` — 纪律检查（每次结果展示前必读）

### 阶段三：进入流程节点时（随流程推进读取）

7. `core/03-error-handling.md` — 故障处理矩阵（进入首个流程节点前读取）
8. `core/04-field-handling.md` — 字段分类与处理规则（进入表单填写节点前必读）
9. `runbooks/{流程}/{编号}-*.md` — 流程节点文件，**按节点顺序逐个读取**，执行完一个再读下一个

> **core/ 全部文档都由主会话读取**：01/02/05 在节点 30 前读取，03/04 在进入流程节点时读取。runbook 节点文件按需逐个加载，避免上下文膨胀。

## 技能触发后的第一件事

**先检查 bsk CLI 就绪，再执行 `recovery/00-resume-protocol.md`** — 快速定位用户当前处于哪个节点。

| bsk 检查结果 | 处理 |
|-------------|------|
| `which bsk` 成功 | 执行恢复协议定位节点 |
| `which bsk` 失败 | → 节点 10（引导安装 browser-skill） |

## 恢复后的处理逻辑

恢复协议定位到节点后，主会话**直接读取对应节点文件并执行**：

| 定位到的节点 | 处理方式 |
|-------------|---------|
| 节点 10 | 读取 `runbooks/common/10-env-detect.md`，引导安装 bsk |
| 节点 20 | 读取 `runbooks/common/20-login.md`，执行登录流程 |
| 节点 30 | 读取 `runbooks/common/30-home.md`，识别意图 → 导航 → 进入对应流程 |
| 填单流节点 | 读取 `runbooks/form-filling/{编号}-*.md`，从当前节点继续执行 |
| 审批流节点 | 读取 `runbooks/approval/{编号}-*.md`，从当前节点继续执行 |
| 发起流程节点 | 读取 `runbooks/start-process/{编号}-*.md`，从当前节点继续执行 |

## 主会话执行职责

主会话**按顺序执行**以下事项：

1. 检查 bsk CLI 可用性
2. 执行恢复协议定位节点
3. **每次用户给出新意图时，重新执行恢复协议**（即使是同一会话内的第二轮对话）——强制重新定位节点、重新读取对应 runbook 文件，禁止复用上一轮的操作模式
4. 处理登录流程（**禁止询问用户选择环境**：用户没说"测试环境"=直接打开正式环境 `https://qy.do1.com.cn/qiqiao2/runtime/`）
5. 进入首页后立即执行 `window.$ai.init()`（**必须**，确保 API 可用）
6. 识别用户意图：**意图不清时必须停下来询问用户**（禁止猜测或自行补全），意图明确时导航到目标页面
7. 按流程路径**逐个读取 runbook 节点文件并执行**，按每个文件末尾"下一节点"声明流转
8. 执行过程中需要用户输入时（多结果/缺值/高危确认），**直接在会话中询问用户**，等待回复后从中断点继续执行
9. 任务完成后向用户展示结果。**展示结果前必须先读取 `core/06-discipline-check.md`**（不对用户展示），然后在回复末尾附加以下提示（必须分行，不可省略）：

```
---
tips：
1、点击 Agent正在控制-中断 不影响技能操作浏览器。
2、完成一次填单或审批后，建议新开一个会话做新任务。
```

主会话**禁止**做的事情：

- 跳过节点直接执行后续操作（必须按 runbook 节点顺序流转）
- 一次读取全部 runbook 节点文件（按需逐个加载）
- 在回复中展示 bsk snapshot 原始输出、内部错误堆栈等过程细节

## 执行纪律

1. **先定位节点，再决定执行内容** — 不假设用户在哪个节点，必须先通过恢复协议确认
2. **严格按节点顺序执行** — 读取对应流程文件夹中的 `{编号}-*.md`，按操作表逐项执行，按"下一节点"声明流转
3. **每步必须有结果** — 执行完一个操作必须确认得到预期结果后才能进入下一步，禁止"假装执行"
4. **用户交互不中断流程** — 需要用户输入时直接询问并等待，用户回复后从当前节点继续，不重新开始
5. **结果展示面向用户** — 仅展示用户需要关注的信息，不展示内部执行日志

### 数据安全与用户交互（必须遵守）

- **多条结果** → 暂停执行，展示选项让用户确认，**禁止**默认选第一个或自行猜测
- **零条结果** → 暂停执行，告知用户并询问是否换关键词，**禁止**自行探测
- **用户未提供值** → 暂停执行，向用户询问，**禁止**编造填入
- **用户没说"全部"** → **禁止**自行批量操作
- **高危操作**（终止/驳回/外部链接）→ 暂停执行，请用户确认
- **严禁**未经确认自动提交/删除/填单

详细约束见 `core/01-global-rules.md` GR-03 / GR-04。
