# 节点 30：首页（意图识别与导航枢纽）

> ⚠️ 开始前先读取 `core/06-discipline-check.md`。

## 你在哪里

已成功登录七巧平台，当前看到七巧首页。这是**意图识别与导航枢纽节点**——主会话识别用户意图后，导航到目标页面，然后**按顺序读取对应流程的节点文件继续执行**。

**本节点是公共节点与流程节点的分界线。**

## 进入本节点后必须先做

**第一步：读取指令参考手册（必须，不可跳过）**

读取 `core/05-commands-reference.md`，确保熟悉 `window.$ai.*` 和 `bsk` 全部指令的用法与约束。

**第二步：执行 `window.$ai.init()`（必须，不可跳过）**

```
bsk evaluate → window.$ai.init()
```

> 进入首页后必须立即执行 `init()`，确保后续 `window.$ai.findDom`、`window.$ai.fillingForm` 等 API 可用。即使登录流程中已执行过，此处也必须再次执行确认。

**第三步：检查用户意图是否明确**

| 情况 | 处理 |
|------|------|
| 用户已说清楚要做什么（如"帮我填个XX请假单"、"审批一下待办"） | 继续导航 |
| 用户意图不明确（如只说"帮我操作一下"、没指定应用名/流程名等） | **停下来询问用户**：去哪个应用？要做什么操作？**禁止猜测或自行补全** |

## 本节点产出

- 识别用户意图（填单 / 审批 / 发起流程）
- 执行首页导航点击（进入应用列表 / 待办列表 / 发起流程弹窗）
- 确定要执行的流程路径，开始读取对应流程的第一个节点文件

## 可执行操作

| # | 操作名 | 用户意图 | 执行内容 | 下一节点 |
|---|--------|---------|---------|---------|
| 1 | 进入应用列表 | 填单、提申请、搜索应用 | 点击"应用列表" | → `form-filling/01-app-list.md` |
| 2 | 进入待办列表 | 审批、看待办、办理 | 点击"待办列表" | → `approval/01-todo-list.md` |
| 3 | 站点记忆直达 | 有缓存且未过期 | `bsk navigate` 到缓存 URL | → 验证后进入对应流程节点 |
| 4 | 查站点记忆 | 需要先检查缓存 | 读取 `site-memory.json` | 视结果回到 op1/3 |
| 5 | 发起流程 | 发起新流程 | 点击"发起流程" | → `start-process/01-process-search.md` |

### 操作 1：进入应用列表

```
bsk evaluate → window.$ai.findDom('应用列表')[0].click()
```

> 如果 `'应用列表'` 找不到，依次尝试 `'全部应用'` 等同义词。若仍找不到，询问用户。

点击成功后 → **读取 `runbooks/form-filling/01-app-list.md`，进入填单流**。

### 操作 2：进入待办列表

```
bsk evaluate → window.$ai.findDom('待办列表')[0].click()
```

> 如果 `'待办列表'` 找不到，依次尝试 `'我的待办'` 等同义词。若仍找不到，询问用户。

点击成功后 → **读取 `runbooks/approval/01-todo-list.md`，进入审批流**。

### 操作 4：查站点记忆

用 Grep 搜索用户 `~/browser-data/site-memory.json` 中的 `APP_NAME`（如已确定）和 `LIST_NAME`（如已确定）关键词。

| 命中情况 | 处理方式 |
|----------|---------|
| 命中且未过期（`verifiedAt` ≤ 30天） | 直接 `bsk navigate` 跳转，验证后读取对应流程的节点文件继续执行 |
| 命中但已过期（> 30天） | 跳转后验证，失败则进入操作 1 |
| 未命中或文件不存在 | 进入操作 1 |

### 操作 5：发起流程

```
bsk evaluate → window.$ai.findDom({ id: 'index-startProcess' })[0].click()
```

> 优先按 `id` 查找；若 `id` 不匹配，降级按 `name: '发起流程按钮'` 查找。若仍找不到，询问用户。

点击成功后 → **读取 `runbooks/start-process/01-process-search.md`，进入发起流程**。

## 用户意图判定

| 用户说的话 | 判定意图 | 执行操作 | 进入流程 |
|-----------|---------|---------|---------|
| "帮我填个单"、"提个XX申请" | 填单 | 操作 1 | 填单流 `form-filling/01` |
| "审批一下"、"看看待办"、"办理"、"驳回" | 审批 | 操作 2 | 审批流 `approval/01` |
| "去XX应用" | 填单（先查站点记忆） | 操作 4 → 操作 1 | 填单流 `form-filling/01` |
| "发个XX流程"、"发起XX申请" | 发起流程 | 操作 5 | 发起流程 `start-process/01` |

## 进入流程节点

导航成功后，主会话按以下步骤进入流程执行：

1. **确认 core 文档已读取** — 进入首个流程节点前，必须已读取 `core/01-global-rules.md`、`core/02-state-model.md`、`core/03-error-handling.md`、`core/05-commands-reference.md`；进入表单填写节点前，还必须读取 `core/04-field-handling.md`
2. **读取流程起始节点文件** — 按上表"进入流程"列读取对应文件（如 `runbooks/form-filling/01-app-list.md`）
3. **按操作表逐项执行** — 根据前置条件选择操作，逐项执行并确认结果
4. **按"下一节点"声明流转** — 每个节点文件末尾声明了下一节点，读取目标文件继续执行，直到节点声明"完成"
5. **用户交互直接进行** — 执行中需要用户输入时（多结果/缺值/高危确认），直接在会话中询问用户，等待回复后从当前节点继续执行，**不中断流程、不重新开始**

## 操作失败处理

| 失败场景 | 处理方式 | 回退 |
|----------|---------|------|
| `'应用列表'` 找不到 | 尝试 `'全部应用'` 等同义词；仍失败则询问用户 | 留本节点 |
| `'待办列表'` 找不到 | 尝试 `'我的待办'` 等同义词；仍失败则询问用户 | 留本节点 |
| 站点记忆 URL 验证失败 | 视为过期，从操作 1 重新导航 | 操作 1 |
| `'发起流程按钮'` 找不到 | 尝试 `'发起流程'` 等同义词；仍失败则询问用户 | 留本节点 |
| 导航后页面无变化 | 用 `bsk snapshot` 检查页面状态，确认是否已跳转 | 留本节点 |

## 用户中断后的继续执行

流程执行中向用户提问后（多结果确认/缺值询问/高危操作确认）：

1. 记录当前所处节点和待处理的操作
2. 等待用户回复
3. 用户回复后，**从当前节点的中断点继续执行**，不重头开始
4. 如果页面状态可能已变化（如会话超时、弹窗关闭），先用 `bsk snapshot` 确认当前页面，再决定是继续执行还是回退节点

**禁止**在用户回复后重新从头执行整个流程——会重复已完成的步骤。
