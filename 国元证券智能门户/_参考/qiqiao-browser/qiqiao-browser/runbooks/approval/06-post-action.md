# 审批流 06：审批后弹窗处理

> ⚠️ 完成后读取 `core/06-discipline-check.md`。

## 你在哪里

审批操作（办理/驳回/加签/委托）或发起流程提交后，出现了需要后续操作的弹窗：**选择下一节点处理人**（选人弹窗）或**填写意见评论**（意见弹窗）。

> 此类弹窗**无法通过 `window.$ai` 元数据定位**，必须使用 `bsk snapshot` 快照识别页面内容并进行交互。

## 本节点产出

- 选人弹窗：已选择处理人并点击确定
- 意见弹窗：已填写（或留空）意见并点击确定
- 无弹窗：确认流程已结束

## 可执行操作

| # | 操作名 | 触发条件 | 执行内容 | 下一节点 |
|---|--------|---------|---------|---------|
| 1 | 检测弹窗类型 | 进入本节点后首先执行 | `bsk snapshot` 快照判断页面类型 | 留在本节点 / 完成 |
| 2 | 选择处理人 | 快照识别为选人弹窗 | 快照定位搜索框 → 搜索 → 选人 → 确定 | → 回到操作 1 |
| 3 | 填写意见 | 快照识别为意见弹窗 | 快照定位输入框 → 填写/留空 → 确定 | → 回到操作 1 |
| 4 | 完成 | 快照确认无弹窗 | 流程结束 | → 完成 |

### 操作循环逻辑

```
进入 `06-post-action.md`
  │
  ▼
操作 1：bsk snapshot 检测弹窗类型
  │
  ├─ 选人弹窗 → 操作 2（选择处理人）→ 回到操作 1
  ├─ 意见弹窗 → 操作 3（填写意见）→ 回到操作 1
  ├─ 无弹窗   → 操作 4（完成）
  └─ 无法识别 → 询问用户当前页面状态
```

> 操作 2 和操作 3 完成后**必须回到操作 1**重新检测，因为可能连续出现多个弹窗（例如选完人后又弹出意见弹窗）。直到快照确认无弹窗，才执行操作 4 完成。

### 操作 1 详细：检测弹窗类型

通过 `bsk snapshot` 获取当前页面快照，根据以下特征判断弹窗类型：

| 弹窗类型 | 页面特征 | 典型元素 |
|----------|---------|---------|
| 选人弹窗 | 搜索框 + 人员/部门列表 + 确定按钮 | 搜索输入框、人员列表、确定/取消 |
| 意见弹窗 | 评论/意见输入框 + 确定按钮 | 评论输入区（input/textarea）、确定/取消 |
| 无弹窗 | 页面已回到待办列表或首页 | 无弹窗遮罩层、无模态框 |

> 如果快照无法判断弹窗类型（例如页面结构不符合上述特征），**询问用户**当前页面显示的是什么内容。

### 操作 2 详细：选择处理人

> 适用场景：审批办理、加签、委托、发起流程后弹出的选人弹窗。

**前置检查**：用户是否已提供处理人姓名？

- **未提供** → **必须先询问用户**要指定哪个处理人，不能跳过
- **已提供** → 继续执行以下步骤

**步骤**：

1. **定位搜索框**：`bsk snapshot` 快照定位选人弹窗内的搜索输入框
2. **输入并搜索**：`bsk fill @eN --value "姓名"` + `bsk press Enter --ref @eN`
3. **查看搜索结果**：再次 `bsk snapshot` 查看搜索结果列表（结果在 dialog 下方以 listitem 展示）
4. **选择目标人员**：`bsk click @eN` 点击目标人员（搜索结果唯一可直接点击）
5. **点击选人弹窗的「确 定」**：关闭选人弹窗，回到办理/审批弹窗
6. **点击办理/审批弹窗的「确 定」**：最终提交

**失败处理**：

| 场景 | 处理方式 |
|------|---------|
| 搜索不到目标人员 | 告知用户未找到，询问是否换关键词或手动选择 |
| 多个同名人员 | 展示列表让用户确认选哪个 |
| 搜索框无法定位 | 询问用户搜索框在页面中的位置 |
| 点击确定后仍弹窗 | 回到操作 1 重新检测 |

### 操作 3 详细：填写意见

> 适用场景：审批办理、驳回后弹出的意见评论弹窗。

**步骤**：

1. **检查用户意图**：用户是否已提供意见内容？
   - **有明确意见**：通过快照定位评论输入框，填写用户提供的意见内容
   - **无明确意见**：**留空，不填写**，直接进入下一步
2. **点击确定**：快照识别确定按钮并点击

> ⚠️ 意见弹窗中，如果用户没有主动提供意见内容，**不要询问用户是否要填写意见**，直接留空并点击确定。

**失败处理**：

| 场景 | 处理方式 |
|------|---------|
| 输入框无法定位 | 询问用户意见输入框在页面中的位置 |
| 填写后内容未显示 | 重新尝试填写；仍失败则告知用户手动输入 |
| 点击确定后仍弹窗 | 回到操作 1 重新检测 |

### 操作 4 详细：完成

快照确认页面无弹窗后，流程结束。

> **审批流不走站点记忆。** 操作完成后直接结束。

## 操作失败处理

| 失败场景 | 处理方式 | 回退 |
|----------|---------|------|
| 快照识别不出弹窗类型 | 询问用户当前页面是什么 | 留在本节点 |
| 选人搜索无结果 | 告知用户，让其提供备选姓名或手动操作 | 留在本节点 |
| 意见输入框定位失败 | 询问用户输入框位置 | 留在本节点 |
| 确定按钮点击无效 | 重新快照确认按钮位置后重试 | 留在本节点 |
| 弹窗循环超过 5 次 | 可能出现异常弹窗，询问用户 | 留在本节点 |
