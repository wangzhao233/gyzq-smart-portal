# D6 第三方应用接入指南

## 1. 文档说明

### 1.1 适用范围
本指南适用于国元证券智能门户系统（元信私有化企微 + 智能门户 + 七巧低码平台）的第三方应用接入开发。主要面向以下场景：
- 企业内部应用集成智能门户待办中心、消息中心、日程中心
- 第三方数据源接入智能门户数据展示
- 基于基础环境（海光CPU + 银河麒麟 V10 Halberd + MySQL）的开发与部署

### 1.2 读者对象
- 应用开发工程师
- 系统集成工程师
- 项目经理
- 技术架构师

### 1.3 术语说明
| 术语 | 说明 |
|------|------|
| SSO | Single Sign-On，单点登录，本项目基于原有SSO账号密码登录 |
| AppID | 应用唯一标识，用于API调用身份识别 |
| AppSecret | 应用密钥，用于签名计算，需严格保密 |
| HMAC | Hash-based Message Authentication Code，基于哈希的消息认证码 |
| SHA256 | Secure Hash Algorithm 256-bit，安全哈希算法256位 |
| MD5 | Message-Digest Algorithm 5，消息摘要算法第5版 |
| REST | Representational State Transfer，表述性状态转移 |
| 门户(PORTAL) | 国元证券智能门户前端应用 |
| 企微(QW) | 元信私有化企业微信应用 |

## 2. 接入概述

### 2.1 1+2+N 模式
国元证券智能门户采用"1+2+N"应用接入架构：
- **1个核心平台**：智能门户基础平台，提供统一的身份认证、权限管理、消息分发等基础能力
- **2个终端入口**：智能门户Web端（PORTAL）和元信企业微信移动端（QW）
- **N个业务应用**：已识别18个需接入的业务应用，包括微盘扩容、新闻公告、七巧plus、云办公系列等

### 2.2 接入场景总览
第三方应用接入智能门户主要涉及以下四种场景：

| 场景 | 说明 | 典型应用 | 工时估算 |
|------|------|----------|----------|
| 待办中心接入 | 将业务应用的待办事项集成到门户待办中心 | OA审批、流程待办 | 3-5人天/应用 |
| 消息中心接入 | 通过门户消息中心发送应用通知、提醒 | 系统告警、审批提醒 | 2-3人天/应用 |
| 日程中心接入 | 将业务日程集成到门户日程中心 | 会议安排、活动日程 | 2-3人天/应用 |
| 数据源接入 | 将业务数据接入门户数据展示 | 报表数据、监控数据 | 1-2人天/数据源 |

## 3. 接入准备

### 3.1 申请AppID/AppSecret
1. **申请流程**：
   - 登录智能门户管理控制台
   - 进入"应用管理" → "第三方应用接入"
   - 填写应用基本信息（应用名称、应用类型、负责人等）
   - 提交申请，等待管理员审批
   - 审批通过后，系统自动生成AppID和AppSecret

2. **密钥管理**：
   - AppSecret在生成时仅显示一次，请务必妥善保存
   - 如密钥泄露，应立即在管理控制台重置
   - 不同环境（开发、测试、生产）使用不同的AppID/AppSecret

## 4. OAuth2.0 单点登录

### 4.1 授权登录概述
智能门户支持基于OAuth2.0协议的单点登录，用户可通过企业微信账号直接登录第三方应用，无需重复输入账号密码。

### 4.2 授权登录流程
1. 用户访问第三方应用
2. 应用重定向到企业微信授权页面
3. 用户确认授权
4. 企业微信回调应用指定地址，携带授权码（code）
5. 应用使用授权码获取用户信息
6. 完成登录

### 4.3 授权URL格式
```
https://域名:端口/connect/oauth2/authorize?appid=CORPID&redirect_uri=REDIRECT_URI&response_type=code&scope=SCOPE&agentid=AGENTID&state=STATE#wechat_redirect
```

### 4.4 参数说明
| 参数名 | 必填 | 说明 |
|--------|------|------|
| appid | 是 | 企业ID（CORPID） |
| redirect_uri | 是 | 授权后重定向的回调链接地址，需进行urlencode编码 |
| response_type | 是 | 固定值：code |
| scope | 是 | 授权作用域：snsapi_base（静默授权）或 snsapi_userinfo（手动授权） |
| agentid | 是 | 应用的agentId |
| state | 否 | 用于保持请求和回调的状态参数，原样带回 |
| #wechat_redirect | 是 | 固定后缀，标识企业微信跳转 |

### 4.5 授权作用域说明
| 作用域 | 说明 | 适用场景 |
|--------|------|----------|
| snsapi_base | 静默授权，用户无感知 | 仅需获取用户身份标识（userid） |
| snsapi_userinfo | 手动授权，需用户确认 | 需要获取用户详细信息（姓名、头像等） |

### 4.6 回调处理
授权成功后，企业微信会携带code参数回调redirect_uri：
```
https://应用回调地址?code=AUTH_CODE&state=STATE
```

应用需使用code换取用户信息：
```python
import requests

def get_user_info(code):
    # 1. 使用code换取access_token
    token_url = f"https://qyapi.weixin.qq.com/cgi-bin/gettoken?corpid={CORPID}&corpsecret={SECRET}"
    token_resp = requests.get(token_url).json()
    access_token = token_resp['access_token']
    
    # 2. 使用access_token获取用户信息
    user_url = f"https://qyapi.weixin.qq.com/cgi-bin/user/getuserinfo?access_token={access_token}&code={code}"
    user_resp = requests.get(user_url).json()
    
    return user_resp
```

### 4.7 安全注意事项
1. **redirect_uri白名单**：需在企业微信管理后台配置可信域名
2. **state参数**：建议使用随机字符串防止CSRF攻击
3. **code有效期**：code有效期为5分钟，需及时使用
4. **HTTPS要求**：生产环境必须使用HTTPS协议

## 5. 签名认证规范

### 5.1 签名算法概述
智能门户API采用两种签名算法：
- **待办中心、日程中心**：MD5(SHA256(...)) 两步哈希签名
- **消息中心**：HMAC-SHA256 直接hex签名

### 5.2 待办中心/日程中心签名算法（MD5(SHA256(...))）

#### 5.2.1 签名步骤
1. **参数排序**：将所有请求参数（不包括sign参数）按参数名ASCII码升序排列
2. **拼接字符串**：将排序后的参数按"参数名=参数值"格式拼接，用"&"连接
3. **SHA256哈希**：对拼接后的字符串进行SHA256哈希，得到哈希值
4. **MD5哈希**：对SHA256哈希值进行MD5哈希，得到最终签名
5. **签名有效期**：签名有效期为5分钟，超时需重新生成

> **注意**：待办中心/日程中心的签名算法为纯哈希签名（MD5(SHA256(...))），**不使用AppSecret参与计算**。AppSecret仅用于消息中心的HMAC-SHA256签名算法（详见5.3节）。

#### 5.2.2 代码示例（Python）
```python
import hashlib
import time
import json

def generate_todo_signature(app_id, params):
    """
    生成待办中心/日程中心API签名
    
    参数:
        app_id: 应用ID
        params: 请求参数字典
    
    返回:
        signature: 签名字符串
        timestamp: 时间戳
    """
    # 1. 添加必要参数
    timestamp = str(int(time.time()))
    params.update({
        'appId': app_id,
        'timestamp': timestamp
    })
    
    # 2. 参数排序
    sorted_params = sorted(params.items(), key=lambda x: x[0])
    
    # 3. 拼接字符串
    sign_str = '&'.join([f"{k}={v}" for k, v in sorted_params])
    
    # 4. SHA256哈希
    sha256_hash = hashlib.sha256(sign_str.encode('utf-8')).hexdigest()
    
    # 5. MD5哈希
    md5_hash = hashlib.md5(sha256_hash.encode('utf-8')).hexdigest()
    
    return md5_hash, timestamp

# 使用示例
app_id = "GY_APP_001"
params = {
    'title': '待办事项测试',
    'description': '这是一条测试待办',
    'assignee': 'user123',
    'dueDate': '2026-07-03 18:00:00'
}

signature, timestamp = generate_todo_signature(app_id, params)
print(f"签名: {signature}")
print(f"时间戳: {timestamp}")
```

#### 5.2.3 代码示例（Java）
```java
import java.security.MessageDigest;
import java.util.*;

public class TodoSignatureGenerator {
    
    /**
     * 生成待办中心/日程中心API签名
     * 
     * @param appId 应用ID
     * @param params 请求参数
     * @return 签名和时间戳
     */
    public static Map<String, String> generateSignature(String appId, Map<String, String> params) {
        Map<String, String> result = new HashMap<>();
        
        // 1. 添加必要参数
        long timestamp = System.currentTimeMillis() / 1000;
        params.put("appId", appId);
        params.put("timestamp", String.valueOf(timestamp));
        
        // 2. 参数排序
        List<String> keys = new ArrayList<>(params.keySet());
        Collections.sort(keys);
        
        // 3. 拼接字符串
        StringBuilder signStr = new StringBuilder();
        for (String key : keys) {
            if (signStr.length() > 0) {
                signStr.append("&");
            }
            signStr.append(key).append("=").append(params.get(key));
        }
        
        try {
            // 4. SHA256哈希
            MessageDigest sha256 = MessageDigest.getInstance("SHA-256");
            byte[] sha256Hash = sha256.digest(signStr.toString().getBytes("UTF-8"));
            String sha256Hex = bytesToHex(sha256Hash);
            
            // 5. MD5哈希
            MessageDigest md5 = MessageDigest.getInstance("MD5");
            byte[] md5Hash = md5.digest(sha256Hex.getBytes("UTF-8"));
            String signature = bytesToHex(md5Hash);
            
            result.put("signature", signature);
            result.put("timestamp", String.valueOf(timestamp));
            
        } catch (Exception e) {
            throw new RuntimeException("签名生成失败", e);
        }
        
        return result;
    }
    
    private static String bytesToHex(byte[] bytes) {
        StringBuilder sb = new StringBuilder();
        for (byte b : bytes) {
            sb.append(String.format("%02x", b));
        }
        return sb.toString();
    }
    
    public static void main(String[] args) {
        String appId = "GY_APP_001";
        
        Map<String, String> params = new HashMap<>();
        params.put("title", "待办事项测试");
        params.put("description", "这是一条测试待办");
        params.put("assignee", "user123");
        params.put("dueDate", "2026-07-03 18:00:00");
        
        Map<String, String> result = generateSignature(appId, params);
        System.out.println("签名: " + result.get("signature"));
        System.out.println("时间戳: " + result.get("timestamp"));
    }
}
```

### 5.3 消息中心签名算法（HMAC-SHA256）

#### 5.3.1 签名步骤
1. **构造待签名字符串**：按固定格式拼接请求头参数
2. **HMAC-SHA256计算**：使用AppSecret作为密钥，对待签名字符串进行HMAC-SHA256计算
3. **转hex编码**：将HMAC-SHA256计算结果转换为十六进制字符串
4. **防重放机制**：请求头包含时间戳和随机数，时间窗口±5分钟，Nonce缓存防止重放

#### 5.3.2 请求头参数说明
| 参数名 | 说明 | 示例值 |
|--------|------|--------|
| X-AppKey | 应用ID | GY_APP_001 |
| X-Timestamp | 请求时间戳（秒） | 1783046400 |
| X-Nonce | 随机字符串（32位） | a1b2c3d4e5f6789012345678901234567890 |
| X-Sign | 签名 | a1b2c3d4e5f6... |

#### 5.3.3 待签名字符串格式
```
X-AppKey={appKey}&X-Timestamp={timestamp}&X-Nonce={nonce}
```

#### 5.3.4 代码示例（Python）
```python
import hmac
import hashlib
import time
import uuid

def generate_message_signature(app_key, app_secret):
    """
    生成消息中心API签名
    
    参数:
        app_key: 应用ID
        app_secret: 应用密钥
    
    返回:
        headers: 包含签名的请求头字典
    """
    # 1. 生成时间戳和随机数
    timestamp = str(int(time.time()))
    nonce = uuid.uuid4().hex
    
    # 2. 构造待签名字符串
    sign_str = f"X-AppKey={app_key}&X-Timestamp={timestamp}&X-Nonce={nonce}"
    
    # 3. HMAC-SHA256计算
    hmac_obj = hmac.new(app_secret.encode('utf-8'), sign_str.encode('utf-8'), hashlib.sha256)
    signature = hmac_obj.hexdigest()
    
    # 4. 构造请求头
    headers = {
        'X-AppKey': app_key,
        'X-Timestamp': timestamp,
        'X-Nonce': nonce,
        'X-Sign': signature,
        'Content-Type': 'application/json'
    }
    
    return headers

# 使用示例
app_key = "GY_APP_001"
app_secret = "your_app_secret_here"

headers = generate_message_signature(app_key, app_secret)
print("请求头:")
for key, value in headers.items():
    print(f"{key}: {value}")
```

#### 5.3.5 代码示例（Java）
```java
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.util.*;

public class MessageSignatureGenerator {
    
    /**
     * 生成消息中心API签名
     * 
     * @param appKey 应用ID
     * @param appSecret 应用密钥
     * @return 包含签名的请求头
     */
    public static Map<String, String> generateHeaders(String appKey, String appSecret) {
        Map<String, String> headers = new HashMap<>();
        
        // 1. 生成时间戳和随机数
        long timestamp = System.currentTimeMillis() / 1000;
        String nonce = UUID.randomUUID().toString().replace("-", "");
        
        // 2. 构造待签名字符串
        String signStr = String.format("X-AppKey=%s&X-Timestamp=%d&X-Nonce=%s", 
                                       appKey, timestamp, nonce);
        
        try {
            // 3. HMAC-SHA256计算
            Mac mac = Mac.getInstance("HmacSHA256");
            SecretKeySpec secretKeySpec = new SecretKeySpec(appSecret.getBytes(StandardCharsets.UTF_8), "HmacSHA256");
            mac.init(secretKeySpec);
            byte[] hmacBytes = mac.doFinal(signStr.getBytes(StandardCharsets.UTF_8));
            
            // 4. 转hex编码
            StringBuilder signature = new StringBuilder();
            for (byte b : hmacBytes) {
                signature.append(String.format("%02x", b));
            }
            
            // 5. 构造请求头
            headers.put("X-AppKey", appKey);
            headers.put("X-Timestamp", String.valueOf(timestamp));
            headers.put("X-Nonce", nonce);
            headers.put("X-Sign", signature.toString());
            headers.put("Content-Type", "application/json");
            
        } catch (Exception e) {
            throw new RuntimeException("签名生成失败", e);
        }
        
        return headers;
    }
    
    public static void main(String[] args) {
        String appKey = "GY_APP_001";
        String appSecret = "your_app_secret_here";
        
        Map<String, String> headers = generateHeaders(appKey, appSecret);
        System.out.println("请求头:");
        headers.forEach((key, value) -> System.out.println(key + ": " + value));
    }
}
```

### 5.4 签名算法对比
| 特性 | 待办中心/日程中心 | 消息中心 |
|------|------------------|----------|
| 算法 | MD5(SHA256(...)) | HMAC-SHA256 |
| 签名有效期 | 5分钟 | ±5分钟时间窗口 |
| 防重放机制 | 时间戳有效期 | Nonce缓存 |
| 参数传递 | 请求参数 | 请求头 |
| 复杂度 | 中等 | 较低 |

## 6. 安全网关配置

### 6.1 配置概述
安全网关用于控制第三方应用对企业微信API的访问，提供身份验证、权限控制、流量监控等安全能力。所有第三方应用在接入企业微信API前，必须完成安全网关配置。

### 6.2 配置步骤
1. 登录企业微信管理后台
2. 点击右上角"安全网关"入口
3. 进入安全网关配置界面

### 6.3 新建资源
在安全网关配置界面，按以下步骤新建资源：

#### 6.3.1 基础设置
| 配置项 | 说明 | 必填 |
|--------|------|------|
| 名称 | 资源显示名称 | 是 |
| 地址 | 后端服务地址 | 是 |
| 端口 | 后端服务端口 | 是 |
| 所属应用 | 关联的企业微信应用 | 是 |

#### 6.3.2 高级设置
| 配置项 | 说明 | 推荐值 |
|--------|------|--------|
| 网关策略 | 选择"网关代理模式" | 网关代理模式 |
| 所属节点 | 勾选部署节点 | 根据实际部署选择 |

### 6.4 配置注意事项
1. **域名要求**：支持IP地址或域名
2. **端口配置**：确保端口未被占用且防火墙已放行
3. **应用关联**：必须关联已创建的企业微信应用
4. **生效时间**：配置保存后需退出移动端企微应用重新进入生效

### 6.5 验证配置
配置完成后，可通过以下方式验证：
1. 退出企业微信移动端应用
2. 重新进入应用
3. 访问需要安全网关保护的资源
4. 检查是否能正常访问

```javascript
wx.config({

    debug: false, // 开启调试模式，调用的所有api的返回值会在客户端alert出来
    appId: 'CORPID', // 必填，企业微信的corpID
    timestamp: timestamp, // 必填，生成签名的时间戳
    nonceStr: nonceStr, // 必填，生成签名的随机串
    signature: signature, // 必填，签名
    jsApiList: ['onMenuShareWechat', 'onMenuShareTimeline', 'getLocation', 'openLocation', 'chooseImage', 'previewImage', 'uploadImage', 'downloadImage', 'chooseWXPay'] // 必填，需要使用的JS接口列表
});
```

### 7.3 签名生成
后端需生成签名，签名算法如下：
1. 使用企业微信提供的jsapi_ticket（通过access_token获取）
2. 拼接字符串：`jsapi_ticket=TICKET&noncestr=NONCESTR&timestamp=TIMESTAMP&url=URL`
3. 对拼接字符串进行SHA1哈希
4. 生成签名

## 11. 数据源接入

### 11.1 接入模式概述
数据源接入支持两种模式：

| 模式 | 说明 | 适用场景 | 优势 | 劣势 |
|------|------|----------|------|------|
| 主动拉取 | 门户定时从数据源拉取数据 | 数据更新频率较低（小时级/天级） | 实现简单，无需推送服务 | 实时性较差 |
| 数据推送 | 数据源主动推送数据到门户 | 数据更新频率较高（分钟级/秒级） | 实时性好 | 实现复杂，需维护推送服务 |

### 11.2 主动拉取模式

#### 11.2.1 接口规范
数据源需提供标准REST接口供门户调用：

| 接口类型 | HTTP方法 | 说明 |
|----------|----------|------|
| 数据列表 | GET | 获取数据列表，支持分页 |
| 数据详情 | GET | 获取单条数据详情 |
| 增量数据 | GET | 获取指定时间后的增量数据 |

#### 11.2.2 数据格式要求
数据源接口返回数据需遵循以下格式：

```json
{
    "code": 0,
    "message": "success",
    "data": {
        "total": 100,
        "pageNum": 1,
        "pageSize": 20,
        "list": [
            {
                "id": "data001",
                "title": "数据标题",
                "content": "数据内容",
                "updateTime": "2026-07-03 10:30:00",
                "extra": {}
```

## 13. 常见问题与排查

### 13.1 签名相关问题

#### 13.1.1 签名验证失败（错误码401）
**可能原因**：
1. AppID或AppSecret错误
2. 参数排序不正确
3. 时间戳超出5分钟有效期
4. 签名算法使用错误（待办中心用MD5(SHA256(...))，消息中心用HMAC-SHA256）

**排查步骤**：
1. 检查AppID和AppSecret是否正确
2. 确认参数按ASCII码升序排列
3. 检查时间戳是否在5分钟有效期内
4. 确认使用的签名算法是否正确
5. 使用日志记录签名过程，与示例代码对比

#### 13.1.2 时间戳过期
**可能原因**：
- 服务器时间与门户服务器时间不同步
- 网络延迟导致请求处理时间过长

**解决方案**：
1. 同步服务器时间：`ntpdate ntp.gyzq.com`
2. 优化网络连接，减少延迟
3. 在签名前获取最新时间戳

### 13.2 接口调用问题

#### 13.2.1 请求频率超限（错误码429）
**可能原因**：
- 单位时间内请求次数超过限制
- 批量操作未控制并发

**解决方案**：
1. 降低请求频率，参考各接口频率限制
2. 使用批量接口减少请求次数
3. 实现请求队列和限流机制
4. 联系管理员调整频率限制

#### 13.2.2 参数错误（错误码400）
**可能原因**：
- 必填参数缺失
- 参数格式错误
- 参数值超出范围

**排查步骤**：
1. 检查请求参数是否完整
2. 验证参数格式（如时间格式、JSON格式）
3. 检查参数值是否在允许范围内
4. 参考接口文档核对参数说明

### 13.3 数据同步问题

#### 13.3.1 数据推送失败
**可能原因**：
- 网络连接问题
- 数据格式错误
- 认证失败

**排查步骤**：
1. 检查网络连通性
2. 验证数据格式是否符合规范
3. 检查认证配置
4. 查看门户日志获取详细错误信息

#### 13.3.2 数据同步延迟
**可能原因**：
- 同步任务执行频率设置过低
- 数据量过大处理时间过长
- 系统资源不足

**解决方案**：
1. 调整同步频率
2. 优化数据查询和处理逻辑
3. 增加系统资源
4. 使用增量同步减少数据量

### 13.4 性能优化建议

#### 13.4.1 接口调用优化
1. **批量操作**：使用批量接口减少请求次数
2. **缓存机制**：缓存不常变化的数据
3. **异步处理**：非关键路径使用异步调用
4. **连接池**：使用HTTP连接池减少连接建立开销

#### 13.4.2 数据同步优化
1. **增量同步**：只同步变化的数据
2. **压缩传输**：对大量数据启用压缩
3. **分页处理**：大数据量分页处理
4. **错峰同步**：避开业务高峰期
