D4 组织架构同步运维指南

文档版本：V1.0
编制日期：2026年7月3日
编制人员：王昭
适用系统：国元证券智能门户（元信私有化企微 + 智能门户 + 七巧低代码平台）

1. 文档说明

1.1 适用范围

本文档适用于国元证券智能门户系统中的组织架构同步功能，涵盖从HR系统到智能门户再到元信（私有化企微）的完整数据同步链路。主要适用于：

  • 系统运维人员日常同步任务执行
  • 同步异常时的故障排查与处理
  • 紧急情况下的手动数据调整

1.2 读者对象

读者角色关注重点
系统运维工程师同步操作流程、监控检查、异常处理
技术支持人员故障排查、数据修复方法
项目经理同步机制理解、风险点掌握
HR系统管理员数据源确认、同步规则理解

1.3 术语说明

术语说明
HR系统指国元证券人力资源管理系统（S3），人员信息唯一数据源
门户中台智能门户后台管理系统，作为数据同步枢纽
元信企业微信私有化部署版本，同步的目标系统之一
增量同步仅同步变更数据（新增/修改/删除），效率高
全量同步同步全部数据，用于数据修复或首次初始化
yglb员工类别字段，控制同步范围
zzzt在职状态字段，控制同步范围

2. 同步架构概述

2.1 同步链路图


┌─────────────┐      ┌─────────────┐      ┌─────────────┐
│   HR系统    │ ──── │  门户中台   │ ──── │   元信      │
│   (S3)      │      │  (数据枢纽) │      │  (私有化企微)│
└─────────────┘      └─────────────┘      └─────────────┘
       │                    │                    │
       │                    │                    │
       ▼                    ▼                    ▼
   人员数据源          数据清洗/转换         用户/组织创建
   组织架构源          规则过滤/校验         权限分配

2.2 门户中台角色定位

门户中台在同步链路中承担数据枢纽角色，主要职责包括：

  1. 数据抽取：从HR系统拉取人员和组织架构数据
  2. 数据转换：统一数据格式，适配元信接口规范
  3. 规则过滤：根据员工类别和在职状态过滤同步范围
  4. 数据推送：将处理后的数据推送到元信系统
  5. 状态管理：记录同步状态，支持增量和全量模式

2.3 同步时间窗口

同步类型执行时间说明
组织架构同步每天凌晨 0:00部门、岗位等组织信息同步
人员信息同步每天凌晨 0:00员工基本信息同步
手动触发同步任意时间运维人员根据需要手动触发

3. 同步规则说明

3.1 员工类别过滤规则

仅同步以下员工类别（yglb字段）的数据：

员工类别代码类别名称是否同步
1正式员工✅ 同步
2合同制员工✅ 同步
5劳务派遣✅ 同步
6实习生✅ 同步
8其他类别✅ 同步
其他代码未定义类别❌ 不同步

3.2 在职状态过滤规则

仅同步以下在职状态（zzzt字段）的数据：

在职状态代码状态名称是否同步
0在职✅ 同步
2内退✅ 同步
5长期病假✅ 同步
其他代码离职/退休等❌ 不同步（执行禁用逻辑）

3.3 禁用逻辑处理

对于离职/退休人员，采用禁用而非删除策略：

  1. HR系统侧：人员状态变更为离职/退休
  2. 门户中台侧：检测到状态变更，标记为禁用
  3. 元信侧：账户状态设置为禁用，但数据保留

重要原则：企微账户不要有删除逻辑，所有账户变更均通过禁用/启用方式处理。

3.4 数据权限控制

  • 人员信息修改权限锁定在门户本地系统
  • 同步后的手工调整仅限应急场景
  • 常规人员信息变更必须通过HR系统发起

4. 同步操作指南

4.1 增量同步操作

增量同步用于日常数据同步，仅处理变更数据：

4.1.1 自动增量同步

系统按预定时间自动执行：


# 查看自动同步任务状态
crontab -l | grep sync

# 查看同步日志
tail -f /var/log/portal/sync/sync.log

4.1.2 手动触发增量同步

当需要立即同步最新数据时，可手动触发：


# 手动触发增量同步
cd /opt/portal/sync
./sync.sh --mode=incremental

# 查看同步进度
tail -f /var/log/portal/sync/incremental.log

操作步骤：

  1. 登录门户中台管理后台
  2. 进入「系统管理」→「数据同步」模块
  3. 选择「增量同步」模式
  4. 点击「立即执行」按钮
  5. 等待同步完成，查看同步日志

4.2 全量同步操作

全量同步用于数据修复或首次初始化，同步全部数据：

4.2.1 自动全量同步


# 查看全量同步任务
crontab -l | grep full

# 全量同步通常在周末或维护窗口执行

4.2.2 手动触发全量同步

重要提示：全量同步会覆盖现有数据，请谨慎操作！


# 手动触发全量同步
cd /opt/portal/sync
./sync.sh --mode=full

# 查看同步进度
tail -f /var/log/portal/sync/full.log

操作步骤：

  1. 登录门户中台管理后台
  2. 进入「系统管理」→「数据同步」模块
  3. 选择「全量同步」模式
  4. 确认操作：系统将提示全量同步风险
  5. 点击「立即执行」按钮
  6. 等待同步完成，查看同步日志

4.3 同步状态查询


# 查询同步状态
curl -X GET "http://localhost:8080/api/sync/status" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json"

# 查询特定用户同步状态
curl -X GET "http://localhost:8080/api/sync/status?userId=12345" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json"

界面查询：

  1. 登录门户中台管理后台
  2. 进入「系统管理」→「数据同步」→「同步状态」
  3. 可按时间范围、同步类型、状态等条件筛选
  4. 查看同步详情：成功/失败/跳过的记录数

6. 异常排查指南

6.1 常见同步问题及解决方案

6.1.1 同步任务未执行

症状：预定时间未执行同步任务

排查步骤：


# 1. 检查crontab任务
crontab -l

# 2. 检查同步服务状态
systemctl status portal-sync

# 3. 检查系统日志
journalctl -u portal-sync -f

# 4. 检查磁盘空间
df -h

解决方案：

  1. 重启同步服务：systemctl restart portal-sync
  2. 手动触发同步：./sync.sh --mode=incremental
  3. 检查磁盘空间，清理日志文件

6.1.2 同步失败

症状：同步任务执行失败，日志中有错误信息

排查步骤：


# 1. 查看错误日志
tail -100 /var/log/portal/sync/error.log

# 2. 检查网络连接
ping hr.example.com
ping yuanxin.example.com

# 3. 检查数据库连接
/opt/portal/sync/check_db.sh

常见错误及解决方案：

错误信息可能原因解决方案
Connection timeout网络连接超时检查网络配置，增加超时时间
Authentication failed认证失败检查账号密码，更新凭证
Data format error数据格式错误检查数据源格式，更新转换规则
Duplicate key主键冲突检查数据源重复记录

6.1.3 邮箱绑定丢失

症状：用户邮箱绑定信息丢失

排查步骤：


# 1. 检查用户邮箱字段
curl -X GET "http://localhost:8080/api/users/{userId}" \
  -H "Authorization: Bearer <token>"

# 2. 检查同步日志中的邮箱字段处理
grep "email" /var/log/portal/sync/sync.log

# 3. 检查HR系统原始数据
curl -X GET "http://hr.example.com/api/users/{userId}"

解决方案：

  1. 手动补充邮箱绑定信息
  2. 检查同步规则中邮箱字段映射
  3. 更新同步配置，确保邮箱字段正确处理

6.2 数据不一致问题

6.2.1 用户状态不一致

症状：同一用户在HR系统和元信中状态不同

排查步骤：


# 1. 比对用户状态
/opt/portal/sync/compare.sh --userId=12345

# 2. 检查状态映射规则
cat /opt/portal/sync/config/status_mapping.json

# 3. 查看同步日志中的状态变更记录
grep "status" /var/log/portal/sync/sync.log | grep "12345"

解决方案：

  1. 手动触发增量同步
  2. 检查状态映射规则是否正确
  3. 必要时执行全量同步

6.2.2 组织架构不一致

症状：部门、岗位等组织信息不一致

排查步骤：


# 1. 比对组织架构
/opt/portal/sync/compare.sh --org

# 2. 检查组织架构映射规则
cat /opt/portal/sync/config/org_mapping.json

# 3. 查看组织架构同步日志
grep "organization" /var/log/portal/sync/sync.log

解决方案：

  1. 手动触发组织架构增量同步
  2. 检查组织架构映射规则
  3. 必要时执行全量组织架构同步

7. 应急处理

7.1 手动调整流程

重要提示：手动调整仅限应急场景，常规变更必须通过HR系统发起！

7.1.1 手动调整用户信息

适用场景：用户信息有误，HR系统无法及时更新

操作步骤：

  1. 登录门户中台管理后台
  2. 进入「用户管理」→「用户列表」
  3. 搜索目标用户：按姓名或工号搜索
  4. 编辑用户信息：修改需要调整的字段
  5. 保存并同步：系统提示是否同步到元信
  6. 填写调整记录：记录调整原因、时间、操作人

# 手动更新用户信息（命令行方式）
curl -X PUT "http://localhost:8080/api/users/{userId}" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "张三",
    "department": "技术部",
    "position": "高级工程师",
    "status": "active"
  }'

# 手动同步到元信
curl -X POST "http://localhost:8080/api/sync/manual/{userId}" \
  -H "Authorization: Bearer <token>"

7.1.2 手动禁用/启用用户

适用场景：用户离职/入职，HR系统未及时更新

操作步骤：

  1. 登录门户中台管理后台
  2. 进入「用户管理」→「用户列表」
  3. 搜索目标用户
  4. 点击「禁用」或「启用」按钮
  5. 填写操作原因
  6. 确认操作

# 手动禁用用户
curl -X POST "http://localhost:8080/api/users/{userId}/disable" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "reason": "手动禁用 - 应急处理",
    "operator": "admin",
    "timestamp": "2026-07-03T10:00:00"
  }'

# 手动启用用户
curl -X POST "http://localhost:8080/api/users/{userId}/enable" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "reason": "手动启用 - 应急处理",
    "operator": "admin",
    "timestamp": "2026-07-03T10:00:00"
  }'

7.2 数据修复方法

7.2.1 数据不一致修复

适用场景：HR系统与元信数据不一致

操作步骤：

  1. 备份当前数据
  2. 执行全量同步（见4.2.2节）
  3. 验证数据一致性（见5.2节）
  4. 记录修复过程

# 备份当前数据
/opt/portal/sync/backup.sh --date=$(date +%Y%m%d)

# 执行全量同步
/opt/portal/sync/sync.sh --mode=full

# 验证数据一致性
/opt/portal/sync/verify.sh --source=hr --target=yuanxin

7.2.2 数据丢失修复

适用场景：同步过程中数据丢失

操作步骤：

  1. 停止同步服务
  2. 从备份恢复数据
  3. 检查数据完整性
  4. 重启同步服务
  5. 执行增量同步

# 停止同步服务
systemctl stop portal-sync

# 从备份恢复数据
/opt/portal/sync/restore.sh --backup-file=/backup/portal_20260702.tar.gz

# 检查数据完整性
/opt/portal/sync/verify.sh --integrity

# 重启同步服务
systemctl start portal-sync

# 执行增量同步
/opt/portal/sync/sync.sh --mode=incremental
