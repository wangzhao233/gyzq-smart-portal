编制人员：王昭

文档版本：V3.0

编制日期：2026-07-18（重大修订：基于门户API文档重新设计）

本文档基于客户OA（SharePoint）REST API + 智能门户数据源API文档（主动拉取v6.0.8 / 数据推送v6.0.8 / 对接指南2.14），指导将OA新闻同步到门户首页。
V3.0 修订：纠正对门户数据源机制的误解——门户主动拉取是POST请求且要求特定JSON格式，不能简单透传SharePoint OData，需要代理层做格式转换。

1. 技术背景纠正

1.1 之前理解的错误

之前以为实际情况
门户发GET请求调SP API门户发POST请求，参数time/nonce/userId/wxUserId/maxCount/currentPage/typeId
数据源URL填 https://portal.oa.gyzq.com/oa-news/...数据源URL填代理服务地址 http://10.0.63.11:8899/api/news
透传SharePoint JSON即可必须转换为门户消息列表格式
门户前端直接渲染门户后端代发请求，Nginx代理非必须

1.2 门户数据源三种模式对比

模式方向实时性适用场景
主动拉取门户→代理→SP实时✅ 新闻列表（主推）
数据推送脚本→SP→推送→门户准实时备选
官方数据源内置实时需部署道一云新闻公告私有化版

2. 最终方案：主动拉取 + JSON格式转换代理

2.1 架构


门户后端(POST) → http://10.0.63.11:8899/api/news
                      ↓
              OaProxyServer (Java/Python)
                 ├─ 接收: time, nonce, userId, wxUserId, maxCount, currentPage, typeId
                 ├─ 注入OA Cookie → 调用 SharePoint REST API
                 ├─ 转换: OData JSON → 门户消息列表JSON
                 └─ 返回: {code:0, data:{value:[...]}}

2.2 门户侧配置（管理员在后台操作）

配置项值
数据源类型主动拉取
组件类型消息列表
接口URLhttp://10.0.63.11:8899/api/news
请求方式POST（门户自动）
认证方式无需（代理内网调用）
自定义参数typeId=gsdt（公司动态，可配多个数据源对应不同分类）

每个新闻分类创建独立数据源：

3. 数据推送模式（备选，用于简单场景）

如果需要，也可以用推送模式：脚本定时从SP拉取 → 转格式 → 推送到门户推送API。

推送接口：POST https://portal.oa.gyzq.com/data_sources/{tenantId}/{dataSourceId}/push

推送体示例：


{
  "secret": "从门户后台获取",
  "jsonData": [
    {
      "infoId": "sp_gsdt_128",
      "title": "国元证券召开2026年中期工作会议",
      "image": "",
      "subTitle": "金融科技部",
      "createTime": "2026-07-15 10:30:00",
      "appName": "老OA",
      "jumpUrl": "http://home.oa.gyzq.com/gsdt/Pages/2026/07/xxx.aspx",
      "dataType": 1
    }
  ]
}

优劣对比：

维度主动拉取（推荐）数据推送
实时性✅ 实时⚠️ 准实时
复杂度代理需接受POST+转换需管理定时任务+去重
网络代理在应用服务器需门户推送API可达
维护代理一个服务代理+定时任务
