## 三、各方案详细分析

### 1. Docling（IBM Research Zurich）⭐ 推荐

**核心能力：**
- 高级 PDF 理解：页面布局分析、阅读顺序、表格结构、代码识别、公式识别、图表理解
- 统一的 DoclingDocument 内部表示，支持导出 Markdown、HTML、JSON、DocTags
- 内置 OCR 支持扫描件和图片
- 支持 VLM（视觉语言模型）如 GraniteDocling
- 内置 chunking 功能，可直接用于 RAG 分块
- 提供 MCP Server 和 API Server（docling-serve）

**优势：**
- 🏆 **格式覆盖最全**（20+ 格式），包括音频、视频、邮件、LaTeX 等少见格式
- 完全本地运行，适合金融行业数据安全要求
- IBM 背书 + Linux Foundation AI & Data 项目，长期维护有保障
- 原生集成 LangChain、LlamaIndex、Crew AI、Haystack
- 活跃社区（281 贡献者，197 releases）
- Python 3.10+，支持 macOS/Linux/Windows

**劣势：**
- 首次安装依赖较大（PyTorch + 多个模型）
- 处理速度相比纯 OCR 方案较慢（深度解析）
- 部分高级功能（VLM）需要 GPU 加速

---

### 2. LlamaParse（LlamaIndex）

**核心能力：**
- LLM 驱动的文档解析，擅长理解复杂布局和语义
- 支持自然语言查询文档内容（agentic 解析模式）
- 自动表格提取和结构化
- 与 LlamaIndex 生态深度集成

**优势：**
- 复杂文档（嵌套表格、多栏排版）解析效果优秀
- 使用简单，API 调用即可
- 支持自定义解析指令（用自然语言描述期望输出）

**劣势：**
- ⚠️ **仅云端 API**，无法自部署，数据需上传至外部服务器
- 💰 按页计费，大量文档成本较高
- 2026年3月原仓库已废弃，迁移至新包 `llama-cloud>=1.0`
- 不支持音频、视频、LaTeX 等格式
- **不适合金融行业数据合规要求（数据外传）**

---

### 3. Marker（datalab.to）

**核心能力：**
- 专注于 PDF/电子书 → Markdown 的高精度转换
- 内置 surya OCR 引擎，扫描件识别准确
- 快速处理，GPU 加速时速度极快
- 支持数学公式、表格、代码块识别

**优势：**
- PDF 转换质量高，特别是学术论文和技术文档
- 速度快（GPU 下比同类方案快数倍）
- 完全开源，可本地运行
- 支持批量处理

**劣势：**
- ⚠️ **格式支持极其有限**：仅 PDF、EPUB、MOBI、图片
- 不支持 Word、Excel、HTML、Markdown 等常见办公格式
- 需要额外工具链补充非 PDF 格式
- 项目更新频率相对较低

---

### 4. Unstructured.io

**核心能力：**
- 智能文档分区（partitioning）：自动识别文档结构
- 针对不同格式的专用策略（PDF、Word、HTML 各有独立解析器）
- 支持元素级提取（标题、段落、表格、图片说明等）
- 提供 SaaS API 和开源自部署两种模式

**优势：**
- 成熟的文档 ETL 管道，从解析到清洗一站式
- 元素级精细提取，适合需要结构化输出的场景
- 社区活跃，文档完善
- 支持 Connectors（S3、Azure、GCS 等云存储直连）

**劣势：**
- 核心 PDF 解析质量不如 Docling 和 Marker
- 高级功能（如 hi_res 策略）依赖额外模型，配置复杂
- 商业 SaaS 版本功能更完整，开源版有功能限制
- 部分 OCR 依赖 Tesseract，中文识别效果一般

## 四、适用场景推荐

### 场景分析（基于国元证券智能门户需求）

| 需求 | 推荐方案 | 理由 |
|------|---------|------|
| **数据安全合规（证券行业）** | Docling > Marker > Unstructured | 必须支持完全本地部署，排除 LlamaParse |
| **WeCom 云盘文档** | Docling / Unstructured | 需处理 Word、PDF、Excel 等混合格式 |
| **SharePoint on-premises** | Docling / Unstructured | 需要 HTML + Office 格式支持 |
| **Obsidian Vault (Markdown)** | Docling / Unstructured | Markdown 直接解析，Marker 不支持 |
| **Confluence** | Docling / Unstructured | HTML 解析 + 结构化提取 |
| **扫描件 PDF (OCR)** | Docling / Marker | 内置 OCR 引擎，中文识别需验证 |
| **统一管道（减少工具链）** | **Docling** | 单一方案覆盖所有格式 |

## 五、最终建议

### 🏆 首选方案：Docling

**理由：**
1. **格式覆盖最全**：单一工具覆盖 PDF、Word、Markdown、HTML、Excel、PPT、图片、音频等 20+ 格式
2. **完全本地部署**：满足金融行业数据安全要求
3. **IBM + Linux Foundation 背书**：长期维护保障
4. **原生 RAG 集成**：内置 chunking，与 LangChain/LlamaIndex 无缝对接
5. **活跃开发**：v2.115.0（2026年7月），1254 commits，281 贡献者

### 备选方案：Marker + Unstructured 组合

如果 Docling 在特定场景（如大量扫描件中文 PDF）效果不理想，可用：
- **Marker** 处理 PDF/扫描件（OCR 质量优秀）
- **Unstructured** 处理其他格式（Word、HTML、Excel 等）

## 六、快速验证计划

1. 安装 Docling：`pip install docling`
2. 准备测试样本：
   - 扫描件 PDF（中文）
   - Word 文档（含表格）
   - Excel 表格
   - HTML 网页
   - Markdown 文件
3. 调用 `DocumentConverter` 测试解析质量
4. 评估中文 OCR 准确率和表格提取效果
5. 根据结果决定是否需要 Marker 作为 PDF 补充
